# Migrating to v0.27.0: QRMI metadata() is now deprecated. Use describe() instead

Up through `v0.26.x`, `metadata()` returned a string-to-string map whose
keys depended on the resource type, and most resource types only reported
`backend_name`.

This release adds `describe()`, which returns a typed `QuantumResourceInfo`:
the resource identity and qubit technology, plus optional details such as
the number of qubits, maximum shots, simulator flag, queue depth and
status. Vendor-specific data that has no dedicated field goes in `extra`.
`metadata()` is now deprecated in every binding. Its behavior is unchanged,
so existing code keeps working, but new code should use `describe()`.

## What's changed

| Language | Deprecated | Replacement |
| :--- | :--- | :--- |
| Rust | `QuantumResource::metadata()` (now `#[deprecated]`) | `QuantumResource::describe() -> Result<QuantumResourceInfo>` |
| C | `qrmi_resource_metadata()` and its `_keys()` / `_value()` / `_free()` helpers (now `@deprecated`) | `qrmi_resource_describe()` and the `qrmi_quantum_resource_info_*()` accessors |
| Python | `QuantumResource.metadata()` (now emits `DeprecationWarning`) | `QuantumResource.describe() -> dict` |
| Lua | `resource:metadata()` (now prints a warning to stderr) | `resource:describe()`, returning a plain Lua table |

### `QuantumResourceInfo` fields

| Field | Type | Description |
| :--- | :--- | :--- |
| `resource_id` | string | The resource identifier, same as `resource_id()`. |
| `resource_type` | string | The resource type, same as `resource_type()`, e.g. `pasqal-local`. |
| `qubit_type` | `QubitType` | One of `superconducting`, `trapped_ion`, `photonic`, `neutral_atom`, `semiconductor` or `other`. |
| `backend_display_name` | string, optional | Human-readable backend name reported by the provider. |
| `num_qubits` | integer, optional | The number of qubits the resource exposes. |
| `processor_name` | string, optional | The hardware generation or processor name. |
| `processor_revision` | string, optional | The processor revision. |
| `description` | string, optional | A free-form description of the resource. |
| `is_simulator` | bool, optional | Whether the resource is a simulator or emulator. |
| `has_queue` | bool, optional | Whether the resource has its own job queue. |
| `max_shots` | integer, optional | The maximum number of shots per job. |
| `pending_job_count` | integer, optional | The number of jobs pending in the queue. |
| `status` | `ResourceStatusCode`, optional | Same value as `status().status`. |
| `last_updated` | string, optional | RFC 3339 timestamp of when the vendor last refreshed this information. |
| `extra` | JSON, optional | Vendor-specific data. |

Optional fields are empty (`None` / `NULL` / `nil`) when the resource type
doesn't report them.

### Where the `metadata()` keys went

| `metadata()` key | Resource types | In `describe()` |
| :--- | :--- | :--- |
| `backend_name` | all | `resource_id` (same value) |
| `session_id` | IBM Quantum Compute Service, IBM Qiskit Runtime Service | `extra.session_id`, when a session is set |
| `acquisition_token` | IQM Server | `extra.acquisition_token`, when set |
| `felis_target` | Alice & Bob Felis | `extra.felis_target` |

## How to migrate

1. **Rust** — Replace `metadata()` with `describe()`. Unlike `metadata()`,
   `describe()` returns a `Result`:

   ```rust
   // Before
   let meta = qrmi.metadata().await;
   println!("{}", meta["backend_name"]);

   // After
   let info = qrmi.describe().await?;
   println!("{} has {:?} qubits", info.resource_id, info.num_qubits);
   if let Some(session_id) = info.extra.get("session_id") {
       println!("session: {session_id}");
   }
   ```

   If you implement the `QuantumResource` trait yourself, implement
   `describe()`. Its default implementation reports only `resource_id`,
   `resource_type` and a `qubit_type` of `other`, so existing
   implementations keep working until you do. Build the result with
   `QuantumResourceInfo::new()` and fill in the optional fields your
   resource knows about.

2. **C** — Replace `qrmi_resource_metadata()` with
   `qrmi_resource_describe()`, then read the fields through the accessor
   functions:

   ```c
   QrmiQuantumResourceInfo *info = NULL;
   if (qrmi_resource_describe(qrmi, &info) != QRMI_RETURN_CODE_SUCCESS) {
       /* handle error */
   }

   char *resource_id = qrmi_quantum_resource_info_resource_id(info);
   printf("resource_id: %s\n", resource_id);
   qrmi_string_free(resource_id);

   QrmiQubitType qubit_type;
   qrmi_quantum_resource_info_qubit_type(info, &qubit_type);
   printf("qubit_type: %s\n", qrmi_qubit_type_to_string(qubit_type));

   uint32_t num_qubits;
   if (qrmi_quantum_resource_info_num_qubits(info, &num_qubits) ==
       QRMI_RETURN_CODE_SUCCESS) {
       printf("num_qubits: %u\n", num_qubits);
   }

   qrmi_quantum_resource_info_free(info);
   ```

   Keep these rules in mind:

   - Release the handle with `qrmi_quantum_resource_info_free()`.
   - Free every string an accessor returns with `qrmi_string_free()`. The
     optional ones (`_backend_display_name()`, `_description()`,
     `_extra()`, ...) return `NULL` when the resource doesn't report that
     field.
   - The scalar accessors (`_num_qubits()`, `_is_simulator()`,
     `_has_queue()`, `_max_shots()`, `_pending_job_count()`, `_status()`)
     return `QRMI_RETURN_CODE_UNSUPPORTED_FUNCTION_ERROR` when the resource
     doesn't report that field.
   - `qrmi_quantum_resource_info_extra()` returns the vendor-specific data as
     a JSON object string.
   - `qrmi_qubit_type_to_string()` returns a static string. Don't free it.

   `examples/qrmi/c/common/common.c` has a `print_resource_info()` helper
   that reads every field.

3. **Python** — Replace `metadata()` with `describe()`, which returns a
   JSON-compatible dict:

   ```python
   # Before
   print(qrmi.metadata()["backend_name"])

   # After
   info = qrmi.describe()
   print(info["resource_id"], info["qubit_type"], info["num_qubits"])
   if info["extra"]:
       print(info["extra"].get("session_id"))
   ```

   Fields the resource doesn't report are `None`. Enum values are strings,
   e.g. `"neutral_atom"` and `"online"`. Calling `metadata()` now emits a
   `DeprecationWarning`.

4. **Lua** — Replace `resource:metadata()` with `resource:describe()`:

   ```lua
   -- Before
   local meta, err = resource:metadata()
   print(meta.backend_name)

   -- After
   local info, err = resource:describe()
   if not info then
     error(err)
   end
   print(info.resource_id, info.qubit_type, info.num_qubits)
   ```

   `describe()` returns a plain Lua table. Fields the resource doesn't
   report are `nil`. `extra` is a JSON object string, not a nested table.
