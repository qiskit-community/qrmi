# Migrating to v0.26.0: Pasqal Local uses Warden sessions with QPU slots

Pasqal Local now uses the Warden session API that supports QPU slots:

- Session creation sends `scheduler_job_id` (previously `slurm_job_id`) and
  `qpu_slots`, read from the optional `QRMI_JOB_QPU_SLOTS` (default `1`).
- Session release sends `DELETE /sessions` with the session in the
  `X-Warden-Session` header instead of putting it in the URL.
- `status()` reports Warden maintenance as `paused` and, when Warden manages
  QPU slots, the available and total slots as `capacity`.

## How to migrate

Upgrade Warden before or together with QRMI: older Warden releases reject
the new session request. Warden keeps accepting the previous request format
and release route, so existing QRMI releases keep working with a new Warden.
