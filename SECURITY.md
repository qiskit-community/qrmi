# Security policy

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities, exploit details, or
credentials in public issues, pull requests, or discussions.

If the repository's Security tab offers "Report a vulnerability", use
that private reporting channel.

If private reporting is unavailable, open an issue asking maintainers
for a private security contact. Include only the request for a contact;
do not include technical details of the suspected vulnerability.

## Information to include privately

To help maintainers investigate, provide:

- The affected QRMI version or commit.
- The backend, operating system, build profile, and relevant configuration.
- Reproduction steps, preferably using synthetic credentials and a local test.
- Expected and observed behavior.
- Potential impact and the conditions required to trigger the issue.
- Sanitized logs or a minimal test case, where useful.

Do not include API keys, bearer tokens, passwords, private keys, or other
live credentials. Replace sensitive values with clearly marked placeholders.

## Coordinating disclosure

Please coordinate public disclosure with maintainers so they can
investigate the report and prepare any necessary fixes and guidance.
